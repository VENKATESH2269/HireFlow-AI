# HireFlow AI

Recruitment Workflow & Intelligence Platform — YottaFlex Round 2 Code Challenge.

## Features

- Deterministic synthetic recruitment data generator (seed `20261022`).
- 12 core domain entities plus append-only application event history.
- Job-related candidate screening based on required skills and experience.
- Interview scheduling records and interviewer-conflict detection.
- Structured interview feedback.
- Salary-band validation for offers.
- Five labelled negative scenarios and a separate ground-truth export.
- CSV, JSON and SQL schema exports.
- FastAPI endpoints, Swagger UI, analytics and integrity checks.
- Automated pytest tests for business rules and anomaly detection.

## Requirements

- Python 3.10 or later recommended.

## Setup (Windows PowerShell)

```powershell
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

## Generate the full dataset

```powershell
python scripts/generate_data.py --seed 20261022
```

For a quick starter dataset:

```powershell
python scripts/generate_data.py --seed 20261022 --scale 0.1
```

The full scale targets:

- 100 requisitions
- 2,000 candidates
- 3,000 applications
- 600 interviews
- 150 baseline offers

The deliberate out-of-band offer is an additional labelled exception.

## Anomaly detection

The system detects five recruitment workflow anomalies:

1. **Duplicate applications:** A candidate applies multiple times for the same requisition.
2. **Interviewer scheduling conflicts:** An interviewer has overlapping interview bookings.
3. **Missing feedback:** An application progresses beyond the interview stage without interview feedback.
4. **Offers outside approved salary bands:** An offer exceeds the requisition's approved compensation range.
5. **Closed requisitions with active applications:** Applications remain active after a requisition is closed.

The anomaly detection endpoint returns issue types, affected record IDs, related IDs and explanatory details.

Ground-truth labels are stored separately from the detector output.

## Reproducibility

The generator seeds Python's random module and Faker.

It resets and rebuilds the database on each run. CSV SHA-256 hashes and row counts are written to `data/source_manifest.json`.

Run twice with the same seed and scale, then compare manifest hashes to verify reproducibility.

SQLite database files are intentionally excluded from Git. Generated CSV, JSON and SQL outputs can be committed if desired.

## Data and privacy

All candidate records are synthetic. Names are generated by Faker and emails use the reserved `example.test` domain.

No external candidate dataset or personal information is used.

`ground_truth.csv` and `ground_truth.json` contain evaluation labels and must remain separate from screening or model input features.

## Data model and cardinality

- Department 1:N JobRequisition
- Department 1:N Interviewer
- JobRequisition 1:N Application
- Candidate 1:N Application
- Candidate 1:1 ResumeArtifact
- JobRequisition N:M Skill through RequisitionSkill
- Candidate N:M Skill through CandidateSkill
- JobRequisition 1:N ScreeningRule (effective-dated)
- Application 1:N Interview
- Interviewer 1:N Interview
- Interview 1:N Feedback (supports multiple panel feedback entries)
- Application 1:N Offer (history / revisions)
- Application 1:N ApplicationEvent (append-only stage history)

## Lifecycle

Application stages:

`APPLIED`, `SCREENING`, `INTERVIEW`, `OFFER`, `HIRED`, `REJECTED`, `WITHDRAWN`.

Allowed transitions are declared in `app/services/workflow.py`.

Offers are checked against the requisition's approved salary band.
